# VS Code Copilot Setup

> **Give GitHub Copilot agent sessions persistent memory across sessions.**

Copilot agent mode starts every session from scratch. Copilot-mem changes that by capturing observations, decisions, and patterns — then injecting relevant context into each new session.

<Info>
**How it works:** VS Code's agent plugin system loads copilot-mem directly — it reads the plugin manifest, runs the lifecycle hooks (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop), and registers the bundled MCP search server. Copilot-mem detects VS Code payloads automatically and normalizes Copilot's tool names (`read_file`, `replace_string_in_file`, `run_in_terminal`, …) into its canonical observation format.
</Info>

## Prerequisites

- [VS Code](https://code.visualstudio.com/) with GitHub Copilot Chat and agent mode
- Agent plugins enabled (`chat.pluginsEnabled`, on by default in recent VS Code)
- [Node.js](https://nodejs.org/) 20+ on your PATH (Bun and uv are auto-installed on first run)

## Installation

### Option 1: Install from source (recommended)

1. Open the Command Palette (`Cmd/Ctrl+Shift+P`)
2. Run **Chat: Install Plugin From Source**
3. Enter the repository URL:

```
https://github.com/ramikhafagi96/copilot-mem
```

VS Code clones the repository, detects the plugin, and loads its hooks, skills, and MCP server.

### Option 2: Install via GitHub Copilot CLI

Plugins installed through the Copilot CLI (under `~/.copilot/installed-plugins/`) are discovered by VS Code automatically:

```bash
copilot plugin install ramikhafagi96/copilot-mem
```

### Option 3: Add as a plugin marketplace

Add the repository to `chat.pluginMarketplaces` in your VS Code settings, then install **copilot-mem** from the Extensions sidebar (filter with `@agentPlugins`):

```json
{
  "chat.pluginMarketplaces": ["ramikhafagi96/copilot-mem"]
}
```

## Verify the installation

1. Start a new Copilot agent session in a project
2. The SessionStart hook starts the copilot-mem worker — check it with:

```bash
npx copilot-mem status
```

3. After ending a session and starting another in the same project, recent memory context appears at the start of the new session
4. The hooks' activity is visible in VS Code's **Output → Chat Hooks** channel

## What works

| Feature | Status |
|---------|--------|
| Observation capture (file edits, terminal commands, reads) | ✅ via PostToolUse hook |
| Context injection at session start | ✅ via SessionStart hook |
| Per-file history timelines before large reads | ✅ via PreToolUse hook |
| Session summaries on stop | ✅ via Stop hook (reads Copilot transcripts) |
| Memory search tools in agent mode | ✅ via bundled MCP server |

Sessions captured from VS Code are attributed to the `vscode` platform — ask Copilot about work you did in earlier sessions and it can search the local memory database.

<Note>
VS Code runs hooks for every tool regardless of the matchers in `hooks.json` (matchers are parsed but not applied). Copilot-mem accounts for this internally — file timelines only inject ahead of read tools, and mutating tools are excluded.
</Note>

## Troubleshooting

**Hooks don't fire:** Confirm the plugin appears under the agent plugins view and is enabled, and check the **Chat Hooks** output channel for errors.

**Worker not running:** Hooks start it automatically, but you can manage it manually:

```bash
npx copilot-mem start    # start the worker
npx copilot-mem logs     # inspect worker logs
```

**No context injected:** Context appears from the second session onward — the first session only captures observations.
